> 来源：[需求澄清](需求澄清.md) ｜ 工具栈：MATLAB（兼容 GNU Octave）｜ 状态：已形成执行基线
>
> 交接入口：build Agent 依次阅读本文件、[协调协议](协调协议.md)、[进度表](进度表.md)、[问题记录](问题记录.md)、[next_plan](next_plan.md) 与 [最新认知](最新认知与执行基线.md)。

## 核心思想

用同一套“BSC/GA 集合构造 → 消息条件化 SC precoding → 码字概率统计 → 无噪声回环 → legacy-spow OOK LLR smoke”协议，逐个验证五个目标高电平概率 `p=P_X(1)`。看板是本 loop 的进度真相源，协议是所有数值口径的唯一裁判。

选择 loop 的原因：五个 `p` 单元的实现、统计、边界和验证流程完全同构；若不固定共同协议，最容易混淆目标 `p`、BSC 交叉概率 `q`、噪声方差和 legacy 统计口径。

## 范围边界

**在范围内**

- 在 `16QAM_Polar/v2/experiments/ook_shaped_polar/` 新建可复用 OOK shaped-polar 验证模块。
- 以论文第二节的二元偏置码字机制为基准，执行 SC precoder + SC decoder 验证。
- 用独立码字样本统计 `p_encoded`，并验证无噪声、正确 LLR、非法输入与有限长度边界。

**明确不做**

- 4-ASK/16-ASK、SCL、CRC、论文第五节 BLER 性能曲线。
- BER/Goodput/Energy 的策略最优性结论。
- 修改 `16QAM_Polar/OOK/`、`16QAM_Polar/ShapedPolarS/` 或为本次实验修改共享 `config.m`。

## 硬约束 vs 自由度

### 硬约束（不可违反）

- `p` 只能表示 `P_X(1)`；所有 BSC 相关计算必须显式使用 `q=min(p,1-p)`，高电平偏置本 loop 中为 `q=1-p`。
- `p=0.5` 必须满足 `S=0`，且不调用不存在的空 shaping-set 逻辑。
- SC 同时用于 precoder 和通信译码；不得静默替换为 SCL。
- 单码字指标必须是 `p_encoded=sum(c==1)/N`，并保存独立样本，不得只保存均值。
- 结果必须放入时间戳 `v2/results/YYYYMMDD_HHMMSS_ook_*`，含参数、种子、CSV/MAT、README、日志、图。
- 单次实验参数通过 `cfg_local` 或函数 `opts` 覆盖；不得改 `config.m`。固定 `N=1024`、`S=ceil(N*(1-h2(q)))`、`K=ceil((N-S)/2)`，并硬检查 `S+K<=N`。
- 长 Monte Carlo 仅由用户授权后本地运行；先做静态检查、smoke、基线比对。
- 每轮实现变更后同步更新本看板、协议（若契约改变）、问题记录与 `周报/原始Shape/README.md`；问题编号连续，解决后改为 🟢。

### 自由度（build Agent 自主）

- 辅助函数的内部实现、表格列的扩展字段、图形样式和小规模 smoke 的独立样本数。
- 使用项目现有 `polar/` 实现或仅将 legacy 函数作为只读对照；前提是协议中的输入输出与口径不变。
- 若有限长度下 SC 无法让目标值落入 CI，可提出 `S` 标定扫描；不得私自改目标概率或删去失败点。

## 执行流程全景（每个单元均走一遍）

1. 由 `p` 导出 `q`、`S=ceil(N(1-h_2(q)))`、`K=ceil((N-S)/2)`，写入本单元元数据。
2. 用 BSC(`q`) Bhattacharyya 递推构造 shaping set `S_set`。对 BER 图的每个横轴 SNR，用 `sigma_ga=10^(-SNR/20)` 的 GA 得到通信排序；排除 `S_set` 后选 `I_set`，其余为 `F_set`，并输出互斥、完备与可行性检查。
3. 对每条消息，把该帧 `I_set` 的真实信息位及 `F_set` 的冻结值作为 SC precoder 已知 decision，只让 `S_set` 由 prior LLR 决定；形成完整 `u` 后 polar transform 得到码字 `c`。
4. 对独立信息消息重复步骤 3，保存逐码字 `p_encoded`；计算均值、标准差、95% CI 与 `target_in_ci`。
5. 按 legacy `spow=mean(c.^2)` 计算该帧噪声，执行无噪声回环、legacy-LRR 对照、非法 `p` / 非 `2^n` 块长 / 维度异常三类检查。
6. 将 smoke 结果写入结果目录；通过才勾选看板。失败时新增问题记录，保留失败数据并停止向下结论。

## 迭代顺序

先实现可复用底座和单元 1 (`p=0.5`)：它证明空 shaping-set、集合分区和无整形基线正确。之后按 `p=0.6 → 0.9` 递进，避免在强偏置失败时无法定位是高偏置有限长度问题还是公共实现错误。

每个单元都只允许在前一单元的公共协议未被改动、并且看板验证列全绿后开始。若协议修改，回归重跑已完成单元的最小 smoke。

## 验证机制

退出码为 0 只说明脚本能运行；每个单元还须以实际生成的码字和实际 OOK 观测验证：

- **正确路径**：校准 smoke 使用不少于 100 条独立码字，正式校准使用不少于 1000 条独立码字和不重复派生 seed；`p_encoded` 均值 95% CI 包含目标 `p` 且半宽不大于 0.01；无噪声信息位零误差；legacy LLR 输入口径与原脚本一致。
- **错误路径**：`p≤0`、`p≥1`、非标量 `p`、非 `2^n` `N`、集合重叠或编码长度不匹配必须报出可诊断错误。
- **边界路径**：`p=0.5` 的 `S=0`；`p=0.9` 的强偏置；CI 不包含目标 `p` 时保留并标记失败，而非用零误差或单点结果掩盖。

BER 图若出现全零错误，只能标注为采样上限，不得用来证明机制或策略优越性。

## 终止条件与人工验收

loop 完成需同时满足：

1. 五个单元的实现、三类验证和结果归档均在看板勾选；
2. 每个目标 `p` 的 95% CI 判断已记录，无未解释的红色问题；
3. 所有脚本、结果 README、L1/L2/L3（如新增函数）与周报同步；
4. 用户审阅汇总图、原始 CSV 与结论边界，明确接受“SC OOK 二元机制已验证”或要求新一轮标定。

本 loop 不因为 BER 曲线“看起来合理”而结束。
