# 知识库与 Harness 治理缺口说明

> 日期：2026-10-10。审计范围：科研知识库、RKS 扫描器及当前状态读取规则。只读审计；未更改扫描器，未启动实验。
> 已读取 `research-spec-checker` 与 `agent-harness-review` 两个 Skill，采用缺陷优先、证据驱动的审查。本文为初版，后续只追加。

知识库完善有一部分属于 harness 治理。可以把知识库看成实验室的说明书和证据索引，把 harness 看成帮助 Agent 正确读取说明书、执行流程、验证产物并判断完成的制度与工具。说明书写得完整，不等于实验已经证明假设；评分工具报告 PASS，也不等于所有研究结论都成立。

本轮的准确判断是：**需要修知识与证据的组织和读取机制，同时继续解决研究本身尚未验证的问题。** 两者应分别验收。需要一起讨论的是研究范围、实际通信要求与证据门槛；已有明确方向的扫描和状态解析缺陷可以直接形成实现方案。

## 1. 缺陷优先审计结果

### [P1] 理论护栏 100% 缺少逐流程检查

依据：`.agents/skills/research-scan-orchestrator/scripts/rks_evaluate.py:193` 的 `score_theory_guardrail` 把所有 L2 正文合并。第205行只要任意 L2 出现一个护栏关键词，就为每份含警告符号的 L1 加分。它没有核对该 L1 关联哪个 L2，也没有限定到 acceptance 章节，更没有检查每个长跑入口是否正确标注权限。

实际执行路径：任意一份 L2 中出现“口径”，8份含警告的 L1 就都可能得到通过。某条实验漏掉其相关护栏时，这个分数仍可保持100%。所以报告中的8/8表示当前关键词算法命中8份文档，不能作为8个领域护栏均正确落实的证据。

修复方向：按当前有效 L1→L2 关联逐条验证结构化验收条目；长跑权限单独检查，缺失则失败。历史正文或无关流程中的关键词不得补足当前流程的护栏。

### [P2] 方法、入口覆盖分母明显小于当前活跃范围

依据：同脚本第40、51–79行。方法只枚举 v2 的 `core/polar/modulation/analysis` 四目录直接子文件；流程只枚举 v2 顶层 `run_*` 加两个手工登记的实验入口。当前 `experiments/` 中实际可枚举31个 `run_*.m`，多数不在该覆盖分母；diagnostics、嵌套模块和v3也未纳入方法分母。

因此35/35、6/6不能说明这轮新增 B4正式入口、冻结码本、独立验证入口及诊断方法全部被扫描。它们可能已有契约，但本评分没有证明其覆盖完整性。评分是限定集合的统计，报告应公开“纳入/排除”的文件清单和理由。

修复方向：使用明确的活跃源码根、递归枚举和路径级ID；排除 results 内源码快照与历史脚本需写入可审计清单，避免把实验快照计作新方法。分别报告v2、v3、诊断及实验入口覆盖，不以 basename 或正文提到名字作为完整契约验收。

### [P2] append-only 文档未被解析为最新有效版本

依据：第129–142行对整份 L1/L2正文做正则和字符串搜索，没有修订ID、supersedes或有效状态解析。只识别 `Hn:` 格式；新 `H3（有限长、指定参数范围）：` 和 OFDM `H2（验证中）:` 不被假设枚举正则识别。即使L2追加了新H3引用，分母仍未纳入它。

旧内容也仍可加分。例如 `l1_probabilistic_shaping.md:12` 的旧H1写“p减小会降低能量”，但其同一公式 `18−16p` 实际随p减小增大；`l1_polar_coding.md:13` 的旧H2仍写GA指导S/I/F，与最新“源熵选S、余位GA选I/F”范围冲突。新认知在其他文档已有追加，但评分器不读取替代关系，因此不能证明最新知识自洽。

修复方向：保留历史正文，在末尾追加机器可读的当前有效快照，含版本、日期、替代对象和证据ID。解析最新有效快照；同ID冲突、无替代指向、修订循环应报错。需要明确生效规则，单纯“最后提到过”仍不足以可靠解析。

### [P2] 引用存在与实验证明被混为同一覆盖指标

依据：第142行只要某个 `domain#Hn` 出现在全部L2正文任意位置就算覆盖；第170–185行只验证L1域文件存在，没有验证引用的Hn是否真实存在，也没有检查声明、实验结果、验收、源码版本或证据文件哈希。

实际执行路径：一个待实施流程或正文中的建议引用也可把假设计为“覆盖”；不存在的 `#H999` 只要域存在，跨层完整性仍可能通过。文件引用可解析不等于假设得到支持。

修复方向：分别报告“有验证流程”“实验执行完成”“验收通过”“支持/反驳/未确定”。每条结论链接唯一实验ID、构造版本、数据、图、审计记录和适用范围。通过自动计数不可以替代证据审核。

### [P2] 读取失败存在静默通过路径

依据：第43–48行读失败统一返回空字符串；第144–145行没有识别到任何假设时返回100%。跨层引用为空及没有警告声明也返回100%。全部L1因编码或权限问题读失败时，假设、引用和护栏三个维度可能仍显示100%。

这不是声称本轮发生读失败，而是代码中可复现的失败处理路径。应显式记录文件读取异常，并令相关维度为ERROR/UNKNOWN，不能用“无内容”解释为“全部通过”。

### [P3] 继任者入口仍引导读取过时状态

依据：`next_plan.md` 的继任者入口仍列 `CLAUDE.md`，但当前根目录该文件不存在；`workbook/README.md` 仍把本机描述为无MATLAB的Octave环境，并列旧环境操作入口。当前 AGENTS 与环境文档已有更新，阅读顺序却没有明确提示这些旧段落已失效。append-only 保留历史是正确的，当前入口应通过有日期的追加有效快照指向 AGENTS 和Windows MATLAB规则。

## 2. 92.5 分到底表示什么

权威历史报告：[rks-20261009_232420.md](../../workbook/knowledge/reports/rks-20261009_232420.md)。该报告的数值可复现，但需要按以下范围解释。

| 维度 | 历史结果 | 实际计算含义 | 不能据此声称 |
|---|---|---|---|
| 方法覆盖 | 35/35，100% | v2四模块直接子文件名有对应L3文件名 | 全仓库方法被覆盖、契约内容正确或与当前源码一致 |
| 流程覆盖 | 6/6，100% | 顶层入口及两个手工入口名称在L2正文出现 | 所有正式实验入口完整建模 |
| 假设覆盖 | 10/16，62.5% | 可匹配旧格式的假设ID在L2正文出现 | 10条均已证明，另外6条均缺实验 |
| 跨层完整性 | 82/82，100% | 匹配到的L3文件名及L1域存在 | Hn有效、证据有效、版本一致或调用关系完整 |
| 理论护栏 | 8/8，100% | 全L2正文存在至少一个关键词 | 每条关联流程均落实了具体护栏 |
| 总分 | 92.5，PASS | 加权元数据启发式得分，阈值75 | 科研正确性、任务完成、论文验收或硬件就绪 |

总分计算：$0.30\times100+0.20\times100+0.20\times62.5+0.15\times100+0.15\times100=92.5$。当前得分不能用来证明全库一致。上一轮报告中“理论护栏100%”应按本说明限缩为脚本关键词统计通过。

## 4. 治理能解决什么，研究还要解决什么

| 工作 | 类型 | 验收方式 |
|---|---|---|
| 当前有效快照、append-only替代链、清单读取与勾选渲染 | harness治理 | 从历史与最新相反状态中正确提取最新；无快照或冲突时明确失败 |
| 递归扫描、显式排除、路径级ID、契约映射 | harness治理 | 活跃文件全量台账；新增入口缺契约时检查失败；快照目录不重复计数 |
| 假设→流程→执行→数据→图→结论追踪 | 知识/证据治理 | 每项能追溯源码版本、参数、seed、验收及适用范围 |
| 每流程护栏、权限和完成判定 | harness治理 | 漏某条护栏、证据丢失、分析失败时任务不自动通过 |
| 等功率下能量优势是否存在 | 研究P1 | 独立功率校准、固定噪声和冻结系数后的正式对照 |
| 接收度量匹配与有限长BER误差 | 研究P2 | 直接似然参考、译码回归和可解释模型误差分解 |
| 27组合、逐信道约束、CSI误差、RF–DC | 研究P3–P5 | 独立验证与硬件标定，不能用文档/评分代替 |

## 5. 建议下一轮治理实施范围

1. 冻结活跃研究范围与历史排除清单，递归生成代码/入口/契约覆盖台账。优先覆盖本轮新增构造、PMF、单载波、B4训练/冻结/两套独立验证及审计入口。
2. 设计append-only的当前有效快照协议：`revision_id`、`supersedes`、版本、状态、证据、作用范围；建立读取器，从完整历史提取唯一当前状态。Markdown仍保留历史，自动生成的机器索引可重建且注明来源。
3. 把假设状态拆成planned/running/supported/refuted/inconclusive/superseded；任务状态拆成未运行/产物已生成/数值通过/视觉通过/文档完成。`[x]`只表示清单定义的交付已经验收，不能代表相关科学假设永远成立。
4. 修RKS检查：分母公开；按路径映射；验证Hn存在；逐L2护栏；读取异常失败；版本与文件证据检验；把研究证据成熟度单独报告。旧92.5保留为旧算法历史结果，新评分不与旧分数直接混比。
5. 加针对失败行为的验证：新入口遗漏、同名函数冲突、H999、过期快照、旧勾选覆盖新状态、缺文件、乱码读取、无关护栏关键词、构造版本不一致、结果缺audit。至少用一个正常路径和一个失败/修复路径说明检查真正能失败。
6. 先做增量治理验收，不重跑已完成正式仿真；找不到可靠证据的科学问题登记为待验证，不补造链接。完成后追加阶段报告和规则反思。

## 6. 值得一起讨论的三个决定

- 研究范围：下一轮知识层的“当前活跃”是否明确以固定16QAM的P1–P5为主，v3通用QAM和OOK作为保留证据的支线？建议如此，避免治理分母混成全历史项目。
- 应用验收：历史BER≤0.1、Goodput≥0.25用于衔接旧图。最终应用通信门槛、CRC和净包吞吐要求是什么？这需要研究目标决定，不能由评分器代选。
- 完成口径：是否接受分别报告“交付清单完成”“假设证据成熟度”“硬件前门禁”三个状态？建议分开，避免重建图全部完成被误读为全课题完成。

规则反思：本审计确认“关键词命中/文件存在”不能代表证据已验证，且append-only需要当前有效状态解析。本轮仅提出修复方案，未实施工具修改；供主任务追加周报与后续治理计划使用。
