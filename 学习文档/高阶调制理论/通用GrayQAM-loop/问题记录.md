## 1. 8-PAM 的 optimized GF(2) relation 尚未形成验证证据 🟢

- **背景**：32/64QAM 需要 8-PAM 轴；论文材料未直接给出可照搬的3×3 polar relation。
- **风险**：把任意搜索矩阵称为论文 relation会造成理论误述。
- **决策**：Unit 0枚举 GF(2)可逆矩阵，在预登记 lambda网格上联合优化 p并冻结最优T；接收端直接以 `z=T^-1b` 的latent labels计算完整星座MAP LLR。证据不足时停止32/64QAM，且搜索矩阵只能称optimized GF(2) relation。
- **状态**：2026-08-28已登记用户选出的T=`[0 0 1;1 0 0;1 1 0]`，mean KL=2.521e-3，max KL约0.0067；对应源码版本已冻结。cell内p未展开，逐点KL/TV尚无完整证据。扩展原无噪声测试覆盖该T及非均匀p，待用户运行后推进。
- **后续证据（2026-08-28）**：用户扩展环回4个均匀基线及16个整形组合全部PASS；非单位relation环回已验证，剩余工作是逐点拟合证据和实际发送经验PMF验证。
- **闭环证据（2026-09-03）**：PAM2/4/8统一进入版本registry；8-PAM在64QAM的lambda=0/0.25/0.5 target→model状态均非fail，最大KL=0.002163、TV=0.02607；有限噪声latent LLR直接枚举对照和真实码字能量/BER链路均通过。矩阵继续只称optimized GF(2) relation。

## 2. “任意 PMF”不能由固定 relation 与有限 `p_i` 保证精确表达 🟢

- **背景**：用户希望统一表示各点概率及相互关系。
- **决策**：API统一用 `p + relation`；目标 PMF求最优 `p`，必须输出 `D_KL(P_target||P_model)`、TV和 solver 状态。允许近似，但禁止宣称任意 PMF 精确可达。
- **状态**：已写入 protocol。

## 3. v2 Octave qammod/qamdemod 仅支持 16QAM 🟢

- **背景**：`v2/compat/octave/qammod.m` 与 `qamdemod.m` 显式拒绝 `M≠16`。
- **决策**：v3 自建通用 Cartesian Gray-PAM/QAM 星座和 MAP/LSE demapper；v2 compat 只作 16QAM外部参考，不修改。
- **状态**：已写入 design/protocol。

## 4. shaped PMF 重归一化会定义性消除能量增益 🟢

- **背景**：若每个 `lambda` 都令实际 shaped 平均能量归一为 1，则不能再以平均发射能量刻画 SWIPT 增益。
- **决策**：每个 `M` 使用均匀星座平均能量计算一次固定 scale；所有 shaped setting 共用。能量验收使用 `fixed_n0`，`fixed_esn0` 仅作另口径比较。
- **状态**：已写入 protocol。

## 5. 16QAM 回归边界容易被误解为复制 legacy shaped BER 🟢

- **背景**：v3 multi-stream relation shaped-polar引入跨层关系，理论上不应复刻v2的四路独立成形结果。
- **决策**：只回归共同正确的 Gray 星座/标签、固定缩放、均匀先验 LLR符号和无噪声链路；v2 保持不动，不在 v3 设置 legacy 运行模式。
- **状态**：已写入 design/protocol。

## 6. `$loop-designer` 默认项目文件与本仓库结构不同 🟢

- **背景**：skill 要求 `project.toml` 与 `harness/knowledge`，本仓库的真相源是 `CLAUDE.md + workbook + workbook/knowledge`。
- **决策**：使用本项目等价规则与 CLI 门禁；clarification 显式记录映射。build 首单元需新增/泛化 v3 CLI wrapper，不能拿 v2-only wrapper 证明 v3 通过。
- **状态**：已记录。

## 7. 论文单整体 polar graph 与 v3 multi-stream 架构曾混称 🟢

- **背景**：论文方法文档描述单个整体 polar codeword分组；v3计划为每个latent bit-level建立一条长度N的独立polar stream。
- **决策**：v3明确命名multi-stream BICM extension，不声称与论文有限长码图等价；严格论文复现不属于本loop验收。
- **状态**：已写入clarification/design/protocol/L1。

## 8. 码字内部符号不能按 iid Wilson样本统计 🟢

- **背景**：shaped-polar码字位置相关且有限长分布可能不完全同分布。
- **决策**：经验PMF与能量以独立帧为统计簇，使用每帧统计量和cluster bootstrap；不使用码字内位置的普通Wilson区间。
- **状态**：已写入protocol机器门禁。

## 9. Shaping bits若不条件于当前payload会得到错误码本 🟢

- **背景**：OOK legacy曾先求shaping bits、再覆盖信息位；经验PMF可能看似合理，但发送码本和BER链路不正确。
- **决策**：发送端必须先写 `u(I)` 与 `u(F)`，再由SC只求 `u(S)`；接收端仅冻结 `F`，活动集为 `I∪S`，只从 `I` 提取payload。无噪声门禁增加改变payload后重新求 `S` 的专项测试。
- **状态**：已写入design/protocol/board。

## 10. Agent 无本地运行时，已采用用户 MATLAB 验证 🟢

- **背景**：执行 `test_unit0_gray_qam` 时 PowerShell 找不到 `octave`；尝试由 WSL 调用时创建实例被系统拒绝。
- **风险**：静态审查不能代替 MATLAB/Octave 的函数兼容性、SC环回和数值 LLR 验证。
- **决策**：由用户在 MATLAB 运行诊断并回传输出，逐项登记已覆盖范围；Agent不能调用运行时不再等同于没有运行证据。
- **状态**：截至2026-08-27，四个已提供的Unit 0诊断均有用户PASS输出；共享底座其他未覆盖门禁仍按board保留，不启动长跑。

## 11. energy-lambda 的模型单调不等于真实码字单调 🟢

- **背景**：`P_X∝exp(lambda|x|^2)`在目标层面必然偏向外圈，但有限长source-MC构造会产生经验PMF损失；只画模型曲线不能证明真实发送码字的能量增加。
- **决策**：统一入口同时保存target/model/empirical PMF；模型能量要求严格递增，经验能量按同seed的独立帧形成相邻配对差，以单侧95% bootstrap下界`>0`为smoke门禁。
- **验证结果**：`20260902_224303_energy_lambda_smoke`的12点全部通过PMF smoke；8组相邻经验能量差的单侧95%下界均大于0（最小为64QAM的0→0.25差：0.03363），模型能量亦全部严格递增，`overall_pass=1`。
- **边界**：64QAM三个经验PMF TV上界为0.0515/0.0586/0.0648，只通过smoke 0.10而未通过正式0.05；这不推翻能量单调结论，但B项继续保持◐。

## 12. 单SNR测试掩盖K向量方向错误 🟢

- **现象**：有限SNR微型检查在`K*frames`处维度错误；此前PMF/能量实验只有单SNR，行向量乘标量能够执行，因此未暴露。
- **根因**：`cellfun`本已返回m×1，额外转置把K变成1×m；多SNR的frames也是行向量，二者不能矩阵相乘。
- **修复与证据**：K/S/F保持列向量；M=8、N=8、SNR=[0,4]微型链路通过，K为3×1、BER_per_bit为3×2；随后全M多SNR coarse完整运行成功。

## 13. source-MC构造seed与运行seed需解耦 🟢

- **背景**：局部BER重复必须固定S/I/F码构造，只改变payload和AWGN；原接口只提供`cfg.seed`，source-MC内部调用`rng`还会改变调用者随机状态。
- **风险**：若每次重复同时换构造，性能波动混合了码本变化；若固定构造seed但不恢复RNG，payload/AWGN又可能被最后一次构造seed接管。
- **修复**：新增`cfg.source_mc_seed`；source-MC构造保存并恢复调用者RNG。MATLAB检查确认调用前后随机序列一致，两个不同runtime seed得到相同S集合/K但不同BER样本。
- **状态**：已通过codecheck和微型运行。

## 14. coarse每条曲线只有一个有效瀑布点 🟢

- **结果**：`20260903_160356_ber_coarse`中12个M/lambda组合均找到候选，中心为8/10/14/16 dB且错误数均超过100；但相邻高2 dB点全部零错误，因此每条曲线只有1个有效点。
- **判定**：coarse完成定位但不满足D门禁的至少2点，且不能据稀疏单seed结果判断lambda排序。
- **处理**：已实现中心附近`-0.5:0.25:1.0 dB`的自适应重复入口；至少3次、至多10次，固定source构造并要求每个有效点累计≥100错误。
- **验证结果**：`20260903_210444_ber_refine`中12条曲线均在3次重复后通过，每条有5–7个有效D点，最低有效错误数104，overall_pass=1。

## 15. 64QAM经验PMF正式0.05门禁 🟢

- **背景**：N=256 energy smoke中，8/16/32QAM三个lambda点的TV上界均≤0.05；64QAM为0.0515/0.0586/0.0648，仅通过0.10 smoke。
- **决策**：不重复已经正式通过的三个M；新增64QAM定向N=1024、80帧、source-MC样本200和2000次frame bootstrap入口。
- **终止条件**：三个lambda点target-model非fail且经验TV上界全部≤0.05；否则继续标记finite-length PMF不足，不用BER通过掩盖B失败。
- **闭环证据**：`20260903_221630_pmf_formal64`中lambda=0/0.25/0.5的TV点估计为0.01261/0.02232/0.02940，帧级bootstrap 95%上界为0.01877/0.02680/0.03310；三个`formal_pass`及`overall_pass`均为1。
